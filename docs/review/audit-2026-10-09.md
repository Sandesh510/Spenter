# SpendCheck audit, 9 Oct 2026

Scope: code read (server functions, ledger and posting rules, Home, Log, Quick Add, Entry builder, Lock, session), `npm run build` (passes), `npx vitest run` (166 pass), `npm audit`, and a market scan. Checked on mock data in the browser and by reading code. Nothing was run against the live Supabase database.

## 1. What is built well

| Area | Why it is good |
| --- | --- |
| Money rules | Integer paise everywhere. Totals and balances are derived from entries, never stored. One ledger file is the source of truth, with tests. |
| Recurring postings | Subscriptions, SIPs, EMIs and insurance use unique keys, so a month is never posted twice, even from two devices. Paused periods are not backfilled. |
| Credit cards | Card spend counts on the day of purchase, a bill payment is a transfer, and Home now shows the bill. This avoids the usual double counting. |
| Budgets | Per month, carried forward, with Needs/Wants/Savings buckets and Safe to spend (balance minus bills still due). Few apps do the "safe to spend" idea. |
| Sessions | Refresh-token renewal, single-flight refresh, one retry after a 401. |
| Saving speed | Two-step Quick Add, save waits only for the POST, parallel server checks, `Server-Timing` headers. |
| Privacy | Amounts hidden by default on Home, scrypt passcode with lockout, per-request ownership checks. |
| Bulk entry | Calendar-based builder avoids parser mistakes. |
| Data out | CSV export, Rules to remember screen. |

## 2. Bugs and risks (ranked)

Confirmed means read in code or reproduced. Likely means it follows from the code but was not reproduced.

### P1: fix soon

1. **No error boundary** (confirmed: none in `src/`). Any render exception blanks the whole app. This already happened once (Home blank from stale cached data). Add a boundary that shows "Something went wrong, Reload" and clears the cached snapshot.
2. **No forgot-password or password-reset flow** (confirmed). A forgotten password locks the user out of their data. Supabase supports reset by email.
3. **Open sign-up** (confirmed: `auth-signup` has no gate). Anyone who finds the URL can create an account on your shared Supabase project and use the functions. After your own account exists, turn off sign-ups in Supabase, or add an invite code.

### P2: should fix

4. **Lists stop at 1000 rows** (confirmed). `GET transactions` and `loadHome` read the month without paging, so a month with more than 1000 entries silently drops the oldest. Rare for one person, but wrong totals would follow. `selectAll` already exists for this.
5. **Month list uses UTC** (confirmed, `Log.tsx:224`). Between midnight and 5:30 am IST on the 1st, the newest month in the Log's month filter is still last month.
6. **Background refresh fails silently** (confirmed, `refreshInBackground` swallows errors). If the refresh after a save fails, Home totals stay old until the next app-foreground refresh, with no hint.
7. **Delete has no undo** (confirmed: `window.confirm`, then soft delete). A native confirm box looks out of place in an installed app. Use an in-app dialog plus an Undo toast (the delete is already soft, so undo is cheap).
8. **Card bill is one month only** (by design, documented). An unpaid bill from last month does not appear in "bill still to pay". Settings, Accounts shows the real owed amount only if an opening balance is set.
9. **Reads that write** (confirmed). Opening Home posts due commitments and premiums and copies budgets. It is safe (idempotent) but makes Home slower after a long gap, and a failure in posting breaks the whole Home load.
10. **Token check cache** (confirmed, my change). A signed-out or revoked token still works for up to 60 seconds on a warm function. Acceptable for this app; noted.
11. **Passcode lock is a screen lock only** (confirmed). The data endpoints do not require the passcode. Someone with the unlocked phone's stored session could call them. Hidden amounts are also hidden in the browser only. Fine for shoulder-surfing, not for device theft. Say so in Rules, or require the passcode before reveal.

### P3: tidy

12. `react-router-dom` is a dependency nobody imports (confirmed), and `npm audit` flags 2 moderate advisories in it. Remove it.
13. No security headers in `netlify.toml` (no CSP, no frame-ancestors, no referrer policy).
14. About 200 inline `style={{}}` remain (Settings 45, Trends 26, Home 21, Log 16, Lent 16, Manual 14), against the project's own rule. Lock and sign-in screens use hard-coded sizes.
15. Android maskable icons reuse the full-bleed logo, so the edge may be cropped. `theme-color` is fixed dark even in light theme.
16. Tests cover `src/lib` rules only. The Netlify functions (posting, EMI delete restore, loan checks) have no automated tests, and there is no end-to-end test. Most past bugs lived in these.
17. No service worker (confirmed). A cold open without network cannot load the app, and the last snapshot only paints after the page itself loads.

## 3. User experience review

- **Good:** two-step add, default account, hidden amounts, Show all categories, calendar builder, toasts after save.
- **Gaps:**
  - Log has no search (by note, amount or category text) and no sort.
  - No "repeat last entry" or favourites. The most common spends are retyped every time.
  - No in-app alert when a budget crosses 80% or 100%, apart from bars on Home.
  - No month-to-month comparison ("Food is 20% above last month").
  - Delete confirmation is a browser dialog.
  - Save errors show as text; a failed save in the calendar builder keeps only the failed rows (good) but the message is easy to miss.
  - Onboarding: a new user sees four sample accounts (HDFC, ICICI, Paytm) that must be renamed.
- **Accessibility:** icon buttons are labelled and chips use `aria-pressed`. The old screens (Lock, sign-in) use text sizes outside the scale and no visible focus ring.

## 4. What other apps offer, and what is worth adding

Market scan (sources below): Indian trackers such as Walnut, Money Manager, Monefy and INDmoney lean on SMS auto-tracking, simple manual logging, bill splitting, and an investment overview. Western apps (Monarch, YNAB) lead with flexible budgeting, bill reminders, net worth, goals, recaps, shared households and loan-payoff planning. SMS-reading apps (PennyWise, Cashiro) sell on-device privacy and duplicate detection.

| Feature | Seen in | Fit for SpendCheck | Effort |
| --- | --- | --- | --- |
| Offline mode (cache the app, queue entries) | Monefy, Pocket-style local apps | High: a phone app that fails offline feels broken | Medium |
| Log search and sort | Almost all | High | Low |
| Repeat last / favourites / recent categories | Fast-entry apps | High, fits the "2-3 taps" goal | Low |
| Daily allowance ("safe to spend per day left") | Budget apps | High: you already have safe to spend and the day of month | Low |
| Month-over-month comparison and a weekly or monthly recap | Monarch, many trackers | High | Low to medium |
| Budget alerts at 80% and 100% | MoneyMap-style, YNAB | High (in-app first, push later) | Low in-app, medium push |
| Net worth view (accounts + savings plans + loans) | Monarch, INDmoney | Medium-high: you already hold the data | Medium |
| Loan prepayment simulator | YNAB | Medium: you have EMI loans with rate and tenure | Medium |
| Forgot password, change password, sign-out of other devices | Standard | High (security) | Low |
| Undo delete | Standard | High | Low |
| Import from bank statement CSV or PDF | Cashiro | Medium: you ruled out bank-specific parsers for now | Medium |
| UPI/SMS auto-import | Walnut, PennyWise | Not possible in a web app (no SMS access). The paste-and-review builder is the closest | n/a |
| Split bills with friends | Walnut, Splitwise-type apps | Low: Money Lent covers one-way loans | High |
| Receipt photo attach or scan | Several | Low-medium | Medium |
| Shared household | Monarch, YNAB Together | Low unless a partner will use it | High |
| Multi-currency | Monefy | Low | Medium |

## 5. Suggested order

1. Error boundary, forgot-password, turn off sign-ups, remove the unused router package.
2. Log search, undo delete, repeat last entry and recent categories, daily allowance.
3. Paging for the 1000-row limit, UTC month fix, visible failure for background refresh.
4. Offline shell (service worker) and queued entries.
5. Month-over-month recap, in-app budget alerts, net worth.
6. Tests for the Netlify functions against a throwaway Supabase project.
